1. Clicking a text file should open it in the internal viewer
-------------------------------------------------------------
Now:   click selects a row; click on the selected row (or double-click)
       dispatches Enter. Enter on a file only sets the message
       "<name> -- no action bound yet (F3 to view)".
Where: Invoke-McKey 'enter' branch, src/Mc.PowerShell/App.ps1 (leaf case).
       Invoke-McViewCurrent in src/Mc.PowerShell/Viewer.ps1 already does the
       work, including checking the entry is a real file on disk.
Decide: mc's Enter on a file *executes* it. We do not execute, and must not
       in read-only mode. Options:
         a) Enter/click views anything viewable. Simple, safe. Diverges from mc.
         b) Enter views text, refuses to execute with a message pointing at F3/F4.
         c) Execute in read-write, view in read-only.
       Leaning (a). Record the choice in docs/COMPAT.md (Enter row is
       "partial"; must not overstate parity).
Also:  Read-McViewerFile detects binary, so a click on a .exe should say so.

Not on TODO.txt, diagnosed earlier -- registry navigation does not open keys
----------------------------------------------------------------------------
Symptom: in a registry panel, Enter/click on a subkey does nothing, silently.
Two faults:
  (a) PSProvider source's Descend uses Convert-Path, which returns the
      provider-internal path (HKEY_LOCAL_MACHINE\SOFTWARE\7-Zip), not a
      drive-qualified one. Nothing can handle it: FileSystem's Test wants a
      drive letter, Test-Path rejects it, Get-McPanelSource throws.
      Fix: build the child path from the current location
      (Join-Path $Location $Entry.Name) and only Convert-Path when the
      provider is FileSystem. Worth a helper next to Get-McParentPath in
      src/Mc.PowerShell/Sources.ps1; Cert: and module drives will hit the same.
  (b) The failure is silent. Set-McPanelLocation returns $false and reverts,
      but Invoke-McPanelEnter discards that with [void] and sets no message.
      Worth fixing regardless of (a).
Tests: tests/KeySequence.ps1 only descends on the filesystem. Add a provider
       case (descend into HKLM:\SOFTWARE\<key>, assert Location changed).
